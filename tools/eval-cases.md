Purpose: prove §0 of `MYBPM-IMPORTS.md` is self-sufficient. Each case is run by ONE fresh subagent
(model `haiku`, `subagent_type: general-purpose`), no other context, and its archive is graded by
`tools/validate-archive.bun.ts`.

## Rounds

The `tools/out/<round>/` snapshots named below are NOT in this repository — a run leaves archives and
reports tied to the stand it was checked against. Reproduce them with `tools/grade-eval.bun.ts`; what the
rounds established is written out here and in §0 itself.

- **Round 1** (2026-09-18) — all 12 cases against the original §0. Snapshot `tools/out/eval-2026-09-18/`.
- **Round 2** — all 12 against the eight §0 repairs. Snapshot `tools/out/eval2-2026-09-18/`.
- **Round 3** — cases 03/05/06/07/11 against the four round-2 repairs. Snapshot `tools/out/eval3-2026-09-18/`.
- **Round 4** — cases 05/07/11 against the three round-3 repairs (composite never degrades to a plain BO,
  `dictionaryFields` on every BO, the `STATIC_TEXT` heading rule promoted to 0.10/0.11).
  Snapshot `tools/out/eval4-2026-09-18/`. 07 and 11 came back 0/0/0 and correct in KIND; 05 regressed to
  0/8/21 on a gap the earlier rounds had not touched — see round 4b.
- **Round 4b** — case 05 only, against the two round-4 repairs («widget» means the six maps of 0.5b and
  nothing else, so `TAB_GROUP` / `PROGRESS_BAR` / `STATIC_TEXT` DO carry `tableColOrderIndex`; and 0.2a
  is not a licence to degrade anything but a missing stand id or code).
  Snapshot `tools/out/eval4b-2026-09-18/` — TWO independent runs of the same case, both kept:
  - `case05` — **0/0/1** (was 0/8/21 in round 4). Both repairs hold: a real `TAB_GROUP` in
    `dynamicFields`, and `TAB_GROUP` / `STATIC_TEXT` x3 / `QUESTIONNAIRE` / `PROGRESS_BAR` /
    `FILE_UPLOAD` all carry their turn in the `tableColOrderIndex` counter (0-9, unbroken).
    The single WARN is a 0.6 slip («Профессиональный опыт» → `Professionalnye_opyt`).
  - `case05b` — **0/0/8**, format-clean but a FLAT 10-field form: no `TAB_GROUP`, no `PROGRESS_BAR`,
    no `QUESTIONNAIRE`, no `FILE_UPLOAD`. This is NOT a 0.2a degrade (nothing was asked for and
    dropped) — it is the case text being one line, «Анкета кандидата HR», while the «what it probes»
    column expects five specific field kinds. A case that only PROBES a construct cannot make the
    model build it. Its 8 WARN are 5 x 0.6 (the label ABBREVIATED before transliterating:
    «Желаемая заработная плата» → `Zhelayemaya_zarplata`) and 3 x 0.8 (`rows: 6` on TEXTAREA).
    0.6 already forbids exactly this in so many words, so no repair was made: the rule is stated,
    the model ignored it.

The snapshots' `report.json` files are regenerated by the grader every time it runs over a directory, so
they always reflect the CURRENT validator — that is deliberate: re-grading an old round after a validator
change is how a severity change is kept honest.

Grade a run directory with `bun tools/grade-eval.bun.ts <runDir> [snapshotDir] [05,07,11]`. Read the
archives by hand as well: the validator checks
FORMAT, not INTENT, and every round so far has had at least one case that scored clean while building
the wrong kind of object.
